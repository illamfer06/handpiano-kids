# Master Prompt

Este proyecto usa la metodología Spec-Driven Development.

## Flujo obligado
1. Spec: definir requisitos y objetivos.
2. Plan: descomponer el trabajo y validar riesgos.
3. Build: implementar incrementalmente.
4. Test: ejecutar validaciones y corregir errores.
5. Simplify: refactorizar y revisar seguridad/claridad.
6. Ship: documentar y preparar entrega.

## Reglas
- No se escribe código sin especificación previa.
- La documentación vive dentro de `dbv-specs-ops/`.
- Todo cambio relevante debe reflejarse en `task.md` y `memory.md`.
- Se debe priorizar claridad, tests y mantenimiento.

## Objetivo del proyecto
Crear una aplicación mínima funcional que sirva de base de trabajo real para el framework `dbv-specs-ops`.
